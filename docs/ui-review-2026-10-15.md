## 発見して修正した問題

検証済みの内容を履歴に保存しただけで「内容が変わったため、再検証が必要です」と表示された。
`SessionVersion` は保存開始・完了でも変わるため、内容の変更の判定には適さなかった。
検証時と現在の編集内容の指紋を比較するように修正した。
実際の編集では古い結果として表示し、検証済みの内容へ戻した場合は有効な結果に戻す。
途中で取り消した検証は未完了のままとする。

修正版で、一時保存と変更理由付き履歴保存の両方を画面から再実行し、誤った表示が出ないことを確認した。

## 自動回帰テスト

`tests/Mconfig.Presentation.Tests` に4件を追加。実際のJSONストアとGit履歴を、一時フォルダーのサンプルに対して使用する。

- 検証後の履歴保存で結果が古くならない。
- 編集すると古くなり、内容を戻すと有効になる。一時保存だけでは判定を変えない。
- 検証結果の受信前に内容が編集されていれば古い結果になる。
- 検証結果の受信前に保存状態だけが変わっていても有効な結果になる。

```powershell
dotnet test tests/Mconfig.Presentation.Tests/Mconfig.Presentation.Tests.csproj -c Release
dotnet build src/mconfig.slnx -c Release
```

4件成功。修正版のReleaseビルドは警告0件・エラー0件。

## 追加の画面改善と15条件での確認

各画面でタブ名を繰り返していた見出しを削除した。
「組み合わせと値」で選択したセルから、既存の割り当てルールへ移動できるようにした。
保存・破棄を伴う画面移動の後、最新のルールから該当行を探し、行を強調して表示する。

絞り込み欄は開閉でき、各条件の名前の下に選択欄を置く。
指定済みの条件は解除できるタグに表示し、表には「すべて」の条件の列だけを表示する。
表の上段見出しを「組み合わせの条件」「割り当て結果」に分け、後者を薄い青、境界を通常の罫線より少し濃い1pxの線にした。線は上段の見出しから表の下端までつなげる。
列の固定は行わず、条件列と結果列を一緒に横スクロールする。グループ見出しも列に追従する。
全条件を指定した場合は、結果の3列だけを表示する。行の内部情報には全条件を保持する。

専用コピーの15条件・27組み合わせで、Computer Useによるフィルター開閉、条件のタグ化、条件列の省略、スクロール後の2段見出しを確認した。
実際のWinFormsコントロールでも、12条件指定、タグ解除での列復帰、全条件指定、選択カテゴリの維持、ルール移動の15条件保持、横スクロール時の見出し位置、最小サイズでの行表示、英語のグループ名を検査した。
表示操作だけでは編集セッションの状態を変更しない。

自動回帰テストは計7件成功（保存・検証4件、ルール移動と絞り込み3件）。
15条件・110,592組み合わせでは、Computer Useのアクセシビリティ情報取得中に応答待ちが続いたため、アプリ単体の大規模データ性能の評価は保留している。
